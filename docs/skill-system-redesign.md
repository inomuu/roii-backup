## 1. ทิศทาง

ย้ายจากโครง RO (skill point + ต้นไม้ต่อคลาส) ไปเป็นโครงเกมกาชา (สกิลตายตัวต่อตัวละคร +
อัพด้วยวัสดุ) **ใช้กับตัวละครทุกตัว** ทั้งคลาสฟรีและ Exemplar

**เหตุผล:**
- ธาตุ 1 คีย์ต่อตัวละคร (ดู `element-weakness-system.md` §4) เป็นไปไม่ได้ถ้าสกิลผูกกับคลาสล้วน —
  5 คลาสทำชาร์ต 8 ธาตุไม่ได้
- **Fire Mage / Ice Mage / Thunder Mage กลายเป็น "คนละตัวละคร" ไม่ใช่ "คนละปุ่มของตัวเดียว"**
  → นี่คือเหตุผลให้เก็บตัวละครให้ครบธาตุ และมันโผล่มาเองจากการจัดรูปสกิล
- วัสดุอัพสกิล = เป้าหมายให้ฟาร์ม (เกม idle ต้องการเหตุผลว่าทำไมต้องตีโซนนี้ต่ออีก 3 ชม.)
  + sink ที่โตตามผู้เล่น + สินค้า commodity ให้ตลาด

> **ยอมรับตรง ๆ:** นี่คือการย้ายเกมจาก "RO-inspired idle" ไปเป็น **"gacha idle"** อย่างตั้งใจ
> (ตัดสิน 2026-09-07 หลังทราบว่า depa ไม่ได้ให้ทุน — scope ที่ pitch ไว้ไม่เป็นข้อจำกัดอีกต่อไป)

## 2. ชุดความสามารถต่อตัวละคร

| ช่อง | จำนวน | หมายเหตุ |
|---|---|---|
| **Basic** | 1 | โจมตีพื้นฐาน · **ไม่ต้องจ่ายวัสดุ** (ในเกมกาชาเป็น node ที่คนอัพเป็นอันสุดท้ายเสมอ = UI ที่เสียเปล่า) |
| **Skill-1 / Skill-2** | 2 | active, auto-cast ตามลำดับ/คูลดาวน์ |
| **Ultimate** | 1 | ปล่อยเมื่อเกจเต็ม · **กดเองได้** (§4) · จุดที่ **cut-in** ทำงาน |
| **Passive** | หลายอัน | ปลดล็อกผ่าน Potential node (§5) |

**ธาตุ:** ตัวละคร 1 ตัว = **1 คีย์ธาตุ** ติดตัว ใช้กับ Skill/Ultimate ทั้งหมด

**เทียบตลาด:** Genshin 3 active · Nikke 3 · HSR 4 · ZZZ 6 · **เรา 4 (รวม Basic)** — เท่า
Blue Archive ซึ่งเป็น auto-battler เหมือนกัน ⚠️ **อย่าขยับขึ้นอีก**: เราเป็นปาร์ตี้ **5 คน**
(กาชาส่วนใหญ่ทีมละ 4) → 3 active × 5 = 15 ความสามารถยิงพร้อมกันบนจอที่ผู้เล่นไม่ได้กด

### แปลงคลาสที่มีอยู่เข้ารูป
คลาสปัจจุบันมี 5–9 โหนด ส่วนใหญ่แค่ยุบ passive ที่ซ้ำแนวแล้วยกหนึ่งตัวขึ้นเป็น Ultimate

| คลาส | ปรับเป็น |
|---|---|
| Archer | เข้ารูปเกือบพอดี — Twin Strafe + Arrow Shower = Skill, **Sharp Focus → Ultimate** |
| Swordsman | Bash + Ignite Break, ยุบ Sword/2H Mastery เหลือ "Weapon Mastery", **Ult ใหม่** |
| Acolyte | Heal + Blessing, **Ult ใหม่** (ฮีลหมู่/ชุบ), Agility Up ย้ายไปเป็นของตัวละครอีกตัว |
| Thief | Shadow Strike + Venom Edge, **Ult ใหม่** |
| **Mage** | ⚠️ เหลือ bolt **ธาตุเดียว** ตามธาตุของตัวเอง + Fireball(AoE) + **Ult ใหม่** — 3-bolt auto-pick ถูกยกเลิก |
| สาย 2-1 (swordmaster/bishop/elementalist/ranger/assassin) | **ยกเลิกทั้งสาย** สกิลกลายเป็นคลังรอเจ้าของ ดู §4.4.4 |

## 3. ลบระบบ SP ทั้งระบบ

**เคาะแล้ว 2026-09-07:** ลบ SP ทิ้ง ออกแบบทรัพยากรใหม่ **แต่ UI ยังเป็นหลอดที่สองใต้ HP เหมือนเดิม**

**สิ่งที่ต้องรื้อ (~48 จุดที่แตะ SP ในสิม):**

| ของเดิม | ทำอย่างไร |
|---|---|
| `Entity.sp` / `max_sp` / sp regen | ลบ → แทนด้วยเกจ (§4) |
| `SkillDef.sp_cost` | ลบ (เป็น 0 ทั้งเกมอยู่แล้ว ยกเว้น swordmaster 3 ตัวที่เป็นของค้าง) |
| `sp_reserve_slots` + `ACTIVE_SLOT_CAP` | ลบ → ตัวคุมบัฟย้ายไป §7 |
| **Mana Spring** (mage +SP/วิ) | เปลี่ยนเป็น **+Charge Rate** |
| **Arcane Ward** | **ถอดออก** (จะออกแบบสกิลใหม่ทั้งระบบอยู่แล้ว) |
| **ยา SP** | **ถอดออก** ⚠️ แก้ `ItemDef` = ขยับ golden ทุกอันที่มันอยู่ในตารางดรอป |
| **INT → MaxSP** | ตัดสายนี้ทิ้ง (INT ยังให้ MATK) ⚠️ เช็กว่า INT ไม่บางเกินไป |

**Implement แล้ว sim 0.0.315** — ผลที่ต่างจากตารางข้างบน:

| จุด | ผลจริง |
|---|---|
| `sp_reserve_slots` / `ACTIVE_SLOT_CAP` | ไม่ได้ลบ แต่แยกออกจาก SP: rename เป็น `loadout_slots` / `loadout_capacity` และ capacity เป็นค่าคงที่ `LOADOUT_CAPACITY = 10` (เดิม `10 + INT/10`) |
| Mana Spring | def ยังอยู่ แต่ไม่ให้อะไร (+Charge Rate รอ kit rewrite) |
| Arcane Ward | ยังอยู่ — มันกิน slot ไม่ได้กิน SP |
| ยา SP | ไม่มีอยู่ในเกมตั้งแต่แรก ไม่ต้องถอด |
| UI หลอดที่สอง | อ่าน `limit_break` / `eff_lb_max` แทน `sp` / `eff_max_sp` |

curve จาก sim-cli ไม่ขยับ (seed 42, 6000 ticks: 203 kills / 15 boss / Lv5)

## 4. Limit Break (ทรัพยากรใหม่ แทน SP)

ออกแบบใหม่ ไม่สืบทอดกติกาของ SP:

| | ค่า |
|---|---|
| สเกล | **0 → cap ที่กำหนดต่อตัวละคร** (เช่น 100/120/140) — ไม่ใช่ stat ที่โตตาม INT |
| เติมจาก | **ตีโดน +A · ร่ายสกิล +B · รับดาเมจ +C** (น้ำหนักกำหนดต่อตัวละคร: แทงค์ชาร์จจากการรับ, DPS จากการตี) + เติมช้า ๆ ตามเวลาเป็นพื้น กันไม่ให้ค้าง |
| ใช้ | เต็ม → ปล่อย Ultimate → กลับเป็น 0 |
| build lever | stat ใหม่ **Charge Rate %** — เกียร์ / Potential stat node / บัฟ เพิ่มได้ (รับช่วงคันโยกที่เสียไปตอนลบ SP) |
| กติกา | **จำนวนเต็มล้วน ไม่มีการสุ่ม** → ไม่กระทบ draw order |

### ชื่อหลอด — **Limit Break** (เคาะแล้ว 2026-09-07)

- **ชื่อในเกม:** `Limit Break` · TH ทับศัพท์ **"ลิมิตเบรก"** (ตามแบบเดียวกับ *คอมมานเดอร์*)
- **loc keys:** `STAT_LIMIT_BREAK` · `UI_LIMIT_BREAK_FULL` · `UI_LIMIT_BREAK_READY` ·
  `SKILL_KIND_ULTIMATE`
- **หลอดที่สองใต้ HP** = หลอด Limit Break · เต็ม → ปล่อย Ultimate

> **ความกำกวมที่เคยห่วง — แก้ที่ต้นเหตุแล้ว (2026-09-07):** ในเกมกาชาอื่น "Limit Break" หมายถึง
> การใช้ตัวซ้ำปลดเพดาน ซึ่งของเราคือระบบ ★ — จึง **เปลี่ยนชื่อระบบ ★ จาก "Resonance" เป็น
> "Memory Fragment"** ทั้งสองคำจึงไม่ทับกันอีก (ดู §4.1)

### 4.1 ที่ build แล้ว (2026-09-07, สาขา `feature/gacha-pivot`)

หลอดอยู่บน **Ultimate ของตัวละคร ไม่ใช่บนตัวละคร** — `SkillDef.lb_max` ที่ไม่เป็นศูนย์คือสิ่งที่
บอกว่าสกิลนั้นเป็น Ultimate และคำตอบของ "ชาร์จยังไง" เขียนอยู่ข้าง ๆ สิ่งที่ค่าชาร์จเอาไปจ่าย

**หลอดขึ้นได้จากหลายทาง ไม่ใช่ทางเดียว** (user 2026-09-07) และแต่ละตัวละครมีทางหลักของตัวเอง

| field | ความหมาย | Seraphine | Rapis |
|---|---|---|---|
| `lb_max` | ขนาดหลอด | 100 | 100 |
| `lb_on_basic` | ต่อการฟันปกติที่เข้า | 4 | 4 |
| `lb_on_skill` | **ต่อการร่ายสกิล 1 ครั้ง** | 10 | 10 |
| `lb_on_hit_taken` | ต่อ 1 instance ที่**รับ** | **12** | 12 |
| `lb_on_break` | ต่อ 1 Toughness break บนสนาม | — | **16** มาจาก passive Ember Cascade ไม่ใช่จากอัลติ |
| `lb_per_second` | ตามเวลา | 2 | 2 |

**หลอดเป็นของ Ultimate แต่ "ทางที่หลอดขึ้น" เป็นของสกิลที่หามาได้** (user 2026-09-07)
`lb_max` อยู่บน Ultimate ส่วนค่าชาร์จรวมมาจากทุกสกิลที่ตัวละครรู้ กฎนี้มีไว้เพื่อไม่ให้แจกทางชาร์จฟรี ๆ

**การชาร์จจาก Toughness break เป็นของสาย Destroyer** ตัวละครสายอื่นจะมีได้ก็ต่อเมื่อ **มีสกิลที่ให้มัน**
Rapis เป็น Striker เธอจึงได้ break-charge จาก **Ember Cascade** ซึ่งเป็น passive ที่ตอบสนองต่อ break
อยู่แล้ว และจ่ายด้วยช่องสกิลที่มันกินไป ไม่ใช่ได้มาเพราะอัลติของเธอแอบให้

⚠️ **บอสควรเป็นข้อยกเว้น** การทุบหลอดบอสแตกเป็นจังหวะของทั้งปาร์ตี้ ไม่ใช่ของคนที่ทุบคนเดียว
ทุกคนควรได้ชาร์จ **แต่ทำเป็น mechanic ประจำบอส ไม่ใช่กฎสากล** (user 2026-09-07) เพื่อให้มันเป็น
เนื้อหาที่ออกแบบไว้ต่อบอส ไม่ใช่กติกาที่ซ่อนอยู่ทั่วเกม ⚠️ ยังไม่ได้ทำ

⚠️ **`lb_on_skill` คิดต่อการร่าย ไม่ใช่ต่อศัตรูที่โดน** AoE ที่กวาดโดนแปดตัวคือการตัดสินใจครั้งเดียว
ไม่ใช่แปดครั้ง ถ้าจ่ายต่อตัว ฝูงใหญ่จะเติมหลอดเต็มทันทีและอัลติจะกลายเป็นของฟรีในห้องที่มอนเยอะ

**Ultimate ไม่มีคูลดาวน์** หลอดคือประตูเดียว และเมื่อร่ายแล้วหลอดกลับเป็นศูนย์
⚠️ ตัวเลือกที่เจอตอน build: ตัวเลือกสกิลอัตโนมัติต้อง **ข้าม Ultimate** ไม่งั้นสกิลที่ไม่มีคูลดาวน์
จะถูกมองว่า "พร้อมเสมอ" แล้วกินทุกเทิร์น

**จูนด้วยการวัด** ลองคูณค่าชาร์จทั้งชุด ×1 ×2 ×3 แล้วนับจำนวนครั้งที่อัลติออกใน 6000 tick

| **×2** | 597 | 188 | **20** |

### กดเอง (manual)
- **กดได้เฉพาะ Ultimate** (เคาะแล้ว) — ไม่เปิดให้กดสกิลอื่น (4 ปุ่ม × 5 คน = 20 ปุ่ม + ต้องมี UI เลือกเป้า = เกมคนละแนว)
- การกด = **`InputEvent` อีกชนิดหนึ่ง** ส่งเข้า `apply_input()` → **replay ยังตรง**, เซิร์ฟเวอร์ตรวจได้เหมือนเดิม
- **ปลอดภัยต่อการโกง:** input นี้ "ขออนุญาต" ไม่ได้ "สั่ง" — เกจไม่เต็ม/ไม่มีเป้า = **no-op เงียบ**
  ตามกติกา `apply_input` เดิม (คนแก้ไคลเอนต์ยิงอัลติรัวไม่ได้ เพราะสิมเป็นคนตัดสิน)
- **ไม่มี latency** — ไคลเอนต์รันสิมเอง กดแล้วติดที่ tick ถัดไป
- UI: แถวภาพตัวละคร 5 คน มี **วงแหวนเกจรอบภาพ** เต็มแล้วกดได้ (ต่อยอด HudBar ทั้ง Godot และ Unity)

### นโยบายออโต้ (ผู้เล่นตั้งไว้ล่วงหน้าต่อตัวละคร)
1. ปล่อยทันทีที่เต็ม · 2. เก็บไว้จนเจอบอส · 3. เก็บไว้จนมีศัตรู ≥3 ตัวในระยะ

> **กฎกันเกมเสียแนว:** โหมดออโต้ต้องไม่แพ้จนคนรู้สึกว่าต้องมานั่งเฝ้า — ใช้จุดยืนเดียวกับ
> "คลิกตีมอน": แอคทีฟได้เปรียบชัดตอนต้นเกม แทบไม่ต่างตอนปลายเกม

## 4.4 Doctrine — บทบาทแทนคลาส

**เคาะ 2026-09-07** เลิกใช้คลาสแบบ RO เป็นแกนจัดทีม เปลี่ยนเป็นระบบบทบาทชื่อ **Doctrine**
แบบเดียวกับ Path ของ HSR และ Specialty ของ ZZZ

**ทำไมถูก** class ถูกทำให้กลวงไปแล้วตั้งแต่ตอนที่ทุกตัวละครมีชุดสกิลตายตัวของตัวเอง
เหลือหน้าที่แค่ชนิดอาวุธ ค่าฐาน และชุดสกิล ซึ่งสองอย่างหลังย้ายไปอยู่ที่ตัวละครหมดแล้ว

### 4.4.1 ห้าสาย

## 4.5 Stat model — ลบหกค่าหลักแบบ RO ไปใช้ stat ปลายแบบเกมกาชา

**เคาะ 2026-09-07** เลิกใช้ STR AGI VIT INT DEX LUK และเลิกให้ผู้เล่นแจกแต้ม
ตัวละครถือ **stat ปลายตรง ๆ** แบบเดียวกับ HSR Genshin ZZZ Nikke

**ทำไมทำตอนนี้** ทุกอย่างที่มันแตะกำลังเปิดอยู่แล้ว ระบบสกิลถูกเขียนใหม่ทั้งชุด แกนธาตุบนเกียร์
กำลังเปลี่ยน SP ถูกลบ และ golden ทั้งชุดขยับอยู่แล้ว ทำทีหลังแปลว่าต้องเขียนเนื้อหาชุดเดียวกันสองรอบ

### 4.5.1 ชุด stat ใหม่

| stat | โตตามเลเวล | หมายเหตุ |
|---|---|---|
| HP | ✅ | |
| **ATK** | ✅ | **ตัวเดียว รวม MATK เข้ามาแล้ว** กายกับเวทแยกกันที่ `damage_type` ของสกิล ไม่ใช่ที่ stat |
| **DEF** | ✅ | **ตัวเดียว รวม MDEF เข้ามาแล้ว** |

**เส้นโค้งต่อตัวละครมีแค่ HP ATK DEF** ตรงกับโมเดลของ Genshin HSR ZZZ WuWa ที่ทุกเกมให้โตแค่สามค่านี้
ส่วน CRIT SPD Haste และ damage bonus เป็นค่าฐานคงที่บวกกับที่ได้จากของสวมใส่
HIT กับ FLEE โตตามเลเวลด้วย แต่เป็น **ฟังก์ชันของเลเวลล้วน เท่ากันทุกตัวละคร** ไม่มีเส้นโค้งรายตัว

**สามแกนความเร็วต้องแยกหน้าที่ให้ชัด** `SPD` = ความเร็วโจมตีปกติ · `Haste` = คูลดาวน์สกิล ·
`Charge Rate` = ความเร็วเติมหลอด Limit Break

**ATK ตัวเดียว** มอนสเตอร์ใช้ `atk` ตัวเดียวอยู่แล้ว การรวมทำให้ผู้เล่นกับมอนใช้โครงเดียวกัน
และแก้ปัญหา dead roll บนเกียร์ ตอนนี้ substat ATK ที่ออกบนไม้เท้าและ MATK ที่ออกบนดาบเป็นค่าที่ไม่มีใครใช้
ซึ่งทำให้ตลาดจืดเพราะของครึ่งหนึ่งที่โรลออกมาไร้ค่า ความต่างกาย/เวทย้ายไปอยู่ที่ damage type
ของสกิลซึ่งตัดสินว่าไปหัก DEF หรือโดน RES แบบไหน `MatkAdd` และ refine MATK ไม่ต้องมีอีก

**DEF ตัวเดียว + Elemental RES%** แกนตั้งรับย้ายจาก MDEF ไปเป็นการต้านทานรายธาตุ ผู้เล่น build
ต้านธาตุตามโซนที่ฟาร์ม ซึ่งผูกกับธีมธาตุประจำ band ที่วางไว้แล้ว ทำให้เกียร์สายตั้งรับมีเหตุผล
และปิดข้อค้างเดิมที่ถามว่าผู้เล่นควรมี weakness mask ไหม RES% ทำหน้าที่นั้นได้ละเอียดกว่า

### 4.5.1.1 HIT และ FLEE — **เก็บไว้ก่อน** เคาะ 2026-09-07

เคยเอนไปทางถอด แต่เก็บไว้เพราะ **การถอดออกคืองาน ไม่ใช่การประหยัด** ต้องแก้ `derived.rs`
แก้มอนทั้ง 67 ตัว แก้ substat บนเกียร์ และที่หนักที่สุดคืออัตราตีพลาดมีผลกับ DPS จริง
พอถอดออก DPS ของทุกคนขยับ ต้องจูนเส้นความยากใหม่ทั้งกระดาน ส่วนการเก็บไว้มีต้นทุนวันนี้เท่ากับศูนย์

**เก็บแบบไม่มีเส้นโค้งต่อตัวละคร** ให้เป็นฟังก์ชันของเลเวลล้วนเท่ากันทุกตัว บวกจากเกียร์
โมเดลการโตจึงยังเหลือเส้นโค้งรายตัวแค่ HP ATK DEF

**ข้อโต้แย้งฝั่งถอดที่ยังจริงอยู่** ไม่มีเกมกาชาสมัยใหม่เกมไหนมีระบบตีพลาด Genshin HSR ZZZ WuWa
ตีเข้า 100% ทุกครั้ง และในเกม idle ผู้เล่นไม่เห็นว่าพลาดและแก้อะไรไม่ได้ ได้ DPS ที่แกว่งโดยไม่รู้สาเหตุ
แต่ **Dragon Traveler ซึ่งเป็น idle เหมือนกันเก็บ accuracy กับ dodge ไว้** จึงไม่ใช่ข้อห้ามของแนวนี้

**ตัดสินทีหลังด้วยตัวเลข** ให้ `sim-cli` รายงานอัตราตีพลาดจริง ถ้ากวนใจค่อยถอดตอนนั้น
เป็นการตัดสินใจที่ย้อนได้ และถ้าวันหนึ่งทำ PvP คู่ค่า accuracy กับ dodge จะยิ่งมีประโยชน์
เพราะ PvP ต้องการค่ารุกที่มีค่ารับคู่กัน

### 4.5.1.2 สูตรการโตของ stat

โครงที่ Genshin HSR ZZZ WuWa ใช้เหมือนกันหมด

```
ค่าจริง = ค่าฐานของตัวละคร × ตัวคูณตามเลเวล(เส้นกลาง) + ก้อนที่ได้ตอนขึ้น tier
```

- **ตัวคูณตามเลเวลเป็นเส้นกลางที่ใช้ร่วมกันทุกตัวละคร** ตัวละครต่างกันแค่ค่าฐาน
  จะปรับเส้นพลังของทั้งเกมก็แก้ตารางเดียว ไม่ต้องไล่แก้ทีละตัว และตัวละครใหม่กรอกแค่ค่าฐาน HP ATK DEF
- **Ascension ของเราคือ Job Level tier** ซึ่งเป็นเพดานของ Potential Board อยู่แล้ว ขึ้น tier
  ได้ก้อน stat หนึ่งก้อน ไม่ต้องสร้างระบบใหม่
- ปลายเกมค่าส่วนใหญ่มาจากเกียร์ ค่าฐานเป็นส่วนน้อยของค่าสุดท้าย โดยเฉพาะ CRIT

**หาตัวเลขจริงโดยไม่ต้องเดา** รัน `sim-cli` ดัมป์ค่า effective ของแต่ละตัวที่ Lv1 10 20 ถึง 70
ใต้ระบบปัจจุบันโดยใช้การแจกแต้มอัตโนมัติจาก `build.rs` แล้วฟิตเป็นเส้นกลางกับค่าฐานรายตัว
จากนั้นรันซีนาริโอเดิมซ้ำเทียบกราฟ ถ้าทับกันแปลว่าเปลี่ยนระบบโดยบาลานซ์ไม่ขยับ

### 4.5.1.3 ผลการวัดจากระบบปัจจุบัน (2026-09-07)

วัดด้วย `cargo run -p sim-cli -- --dump-stats 70` ซึ่งเป็นเครื่องมืออ่านอย่างเดียว
พ่นค่า effective ของทั้ง 5 คลาสที่ Lv1 ถึง 70 โดยไม่ใส่เกียร์ ใช้การแจกแต้มมาตรฐานของ `build.rs`

**สามข้อที่วัดได้ และเปลี่ยนรูปของโมเดล**

**1. ATK โตเป็นเส้นตรง** ฟิต `base + rate × level` ได้ error 2 ถึง 8% สำหรับค่าที่คลาสนั้นใช้จริง
แต่ ⚠️ **อัตราต่อคลาสที่ฟิตได้ใช้ไม่ได้** เพราะมันฝังการแจกแต้มแบบเก่าไว้ข้างใน เห็นชัดที่ thief
ซึ่งได้แค่ 0.51 ต่อเลเวลเพราะแต้มไปลง AGI ไม่ใช่ ATK และ build สายหลบกับสายตีไวจะไม่มีอีกแล้ว
**สิ่งที่ใช้ต่อได้คือรูปของเส้น (เส้นตรง) กับสเกลรวม** ไม่ใช่ตัวเลขรายคลาส

**2. HP ไม่ใช่เส้นตรงและไม่ใช่พหุนามง่าย ๆ** ฟิตดีกรีสองยังพลาดถึง 22% **แต่ไม่ต้องฟิตเลย**
เพราะเส้น HP ของ RO ที่ใช้อยู่คือ `ro_base_hp(max_hp, level, hp_increase, hp_factor)` ซึ่งมี
ค่าประจำคลาสอยู่แล้วใน `game_data.json` **เก็บฟังก์ชันนี้ไว้ทั้งดุ้น** ได้ HP ที่ตรงกับของเดิมเป๊ะ
โดยไม่ต้องจูนอะไรใหม่ ส่วน VIT ที่เคยคูณเพิ่มหายไปพร้อมหกค่าหลัก จึงต้องพับส่วนนั้นเข้าไปในค่าประจำคลาส

**3. DEF ในระบบปัจจุบันไม่โตเลยถ้าไม่ใส่เกียร์** `hard_def` คงที่ทั้งเกม 4 ถึง 8 แต้ม
ส่วนที่โตคือ `soft_def` ที่มาจาก VIT ⚠️ **แปลว่าการให้ DEF โตตามเลเวลเป็นการเปลี่ยนพฤติกรรม
ไม่ใช่การย้ายของเดิม** ต้องตั้งใจเลือก ถ้าอยากรักษาความรู้สึกเดิมให้ตั้งอัตราโตใกล้ soft_def เดิม
ซึ่งอยู่ราว 0.6 ถึง 0.8 ต่อเลเวล

**สเกลรวมที่ต้องรักษาไว้** นี่คือส่วนที่มีค่าที่สุดของการวัด เพราะค่ามอนทั้ง 67 ตัวถูกจูนให้เข้ากับสเกลนี้

### 4.5.1.6 สไลซ์ที่สอง — ATK มาจากเส้นที่เขียนไว้ ไม่ใช่จากหกค่าหลัก (2026-09-07)

### 4.5.1.7 สเกลเลข ×10 (2026-09-07)

เลขเดิมเล็กเกินไปจนเปอร์เซ็นต์ปัดทิ้ง ATK 122 เจอ substat +2% ได้ 2.44 เหลือ 2 อ้างอิงของจริง
HSR ค่าฐานที่เลเวลสูงสุด ATK 654 HP 1,241 DEF 485-601 · Genshin 5★ ATK ฐาน ~334 HP ~10,000-16,000

**คูณ 10 ทุกอย่างที่คู่กัน** ATK · HP · DEF · MDEF ของทั้งผู้เล่นและมอน · ตาราง `level_base` ·

flat ATK ของ mastery · Apex ต่อแต้ม · Bulwark

**ไม่คูณ** ทุกอย่างที่เป็น bp อยู่แล้ว · HIT และ FLEE เพราะเทียบกันเอง ไม่ได้เทียบกับดาเมจ ·

|---|---|---|

1. **มอนไม่ได้ใช้ค่าจาก monster def** แต่ใช้ตาราง `level_base` และ **DEF ของมันคือเลเวลของมันเอง**

สูตรไหนที่อ่านค่า stat เป็นเปอร์เซ็นต์ต้องหารมันกลับ และตอนนี้มีสูตรเดียวคือ freeze resist

### 4.5.1.8 DEF ตัวเดียว และสูตรลดดาเมจแบบเกมกาชา (2026-09-07)

**MDEF หายไปจากทางเดินของดาเมจ** ดาเมจกายและเวทเจอ **DEF ตัวเดียวกัน** และสิ่งที่บอกว่าหมัดนั้น
เป็นอะไรคือ **ธาตุของมัน** ไม่ใช่ว่ามันไปเจอค่าเกราะตัวไหน

**สูตรเดียว แทนที่สองชั้นแบบ RO**

```
ดาเมจที่ผ่าน = ดาเมจ × K / (DEF + K)      โดย K = 500 + 5 × เลเวลผู้โจมตี  (สเกล ×10)
```

เลือกทรงนี้แทนสองชั้นเดิม (ลดเป็น % แบบ diminishing แล้วลบแบบ flat) ด้วยเหตุผลสองข้อ

1. **การลบแบบ flat ทำให้หมัดเล็กกลายเป็นศูนย์** ซึ่งเป็นเหตุผลที่เทสต์เก่าบางอันต้องใช้ดาเมจ 1000
   ถึงจะวัดอะไรได้ สูตรใหม่เป็นสัดส่วนล้วน หมัดเล็กก็ยังเข้าตามสัดส่วน
2. **K ผูกกับเลเวลผู้โจมตี** เกราะจึงมีค่าเป็นสัดส่วนคงที่ตลอดเกม ไม่ใช่แข็งขึ้นเรื่อย ๆ ตามตัวเลข
   ที่โตขึ้น ซึ่งเป็นสิ่งที่สูตรค่าคงที่ตายตัวจะเป็น

`Damage` จึงต้องพก **เลเวลของผู้โจมตี** ติดไปกับแพ็กเก็ต และทุกแหล่งดาเมจต้องใส่ให้ถูก

**เทียบกับเกมอื่น** สูตรที่ใช้กลายเป็นสูตรของ Genshin เป๊ะ ๆ

| เกม | ดาเมจที่ผ่าน |
|---|---|
| **Genshin** | `K / (DEF + K)` · **K = 5 × เลเวลผู้โจมตี + 500** ← ของเรา |
| HSR | `K / (DEF + K)` · K = 10 × เลเวลผู้โจมตี + 200 |
| PoE | `1 − Armour / (Armour + 5 × ขนาดหมัด)` ผูกกับขนาดหมัด ไม่ใช่เลเวล เพดาน 90% |
| Diablo 4 | ไม่เปิดสูตร เพดาน 85% มี armour penetration แฝงตามเลเวล |

**เลือก Genshin ไม่ใช่ HSR** (user 2026-09-07) เพราะ **HSR เป็นเกมเทิร์นเบส** โมเดลดาเมจต่อเทิร์น
ของมันคนละแบบกับเกมเรียลไทม์ ทั้งสองสูตรต่างกันจริงแค่ช่วงต้นเกม ที่เลเวล 1 ค่า K คือ 505 กับ 210
คือ HSR ให้ DEF มีน้ำหนักกว่ามากตอนต้น ส่วนที่เลเวล 70 แทบเท่ากันที่ 850 กับ 900

⚠️ **PoE เป็นตัวที่ต่างจริง** เกราะผูกกับขนาดหมัด เก่งกับหมัดเล็กจำนวนมาก ไร้ผลกับหมัดใหญ่หมัดเดียว
ซึ่งเป็นแกนที่เข้ากับ Toughness ของเราพอดีเพราะเรามีทั้งหมัดรัวและหมัดใหญ่ตอนหลอดแตก
เก็บไว้เป็นทางเลือกของเกราะคนละชนิดในอนาคต

⚠️ **ยังไม่มีเพดานการลดดาเมจ** สูตรเข้าใกล้ 100% แต่ไม่ถึง ที่ DEF 530 เลเวล 70 ลดได้ 38%
จะถึง 85% ต้องมี DEF ราว 4,800 ซึ่งเกียร์ปลายเกมอาจไปถึง D4 ใช้เพดาน 85% PoE ใช้ 90% ยังไม่เคาะ

⚠️ **freeze resist** เคยอ่าน MDEF เป็นเปอร์เซ็นต์ ตอนนี้มอน **ไม่มี RES พื้นฐาน** (user 2026-09-07)
สูตรนั้นจึงเหลือแค่โอกาสของสกิลเอง และ Elemental RES% ที่จะมาทีหลังจะเป็นตัวรับหน้าที่ต้านสถานะ

**ผลกระทบกับเส้นความคืบหน้า** 112 / 200 kills ที่ t3000 / t6000 เทียบกับ 112 / 205 ก่อนสไลซ์นี้
โซนและเลเวลตรงกันทุกจุด

### 4.5.1.9 หกค่าหลักหยุดโต และไม่มีสูตรไหนอ่านมันอีกแล้ว (2026-09-07)

ไม่ได้ลบฟิลด์ทิ้ง แต่ทำให้ **ไม่มีอะไรเป็นผลจากมัน** ซึ่งเป็นขั้นที่ทำให้การลบฟิลด์จริง ๆ ปลอดภัย

| เคยมาจาก | ตอนนี้ |
|---|---|
| ATK ← STR / DEX | **เส้นที่เขียนไว้ต่อตัวละคร** (§4.5.1.6) |
| MATK ← INT | **ค่าเดียวกับ ATK** |
| MaxHP ← VIT | **เส้น HP ของคลาสล้วน** ส่วน passive อย่าง Endure ให้ **%MaxHP ตรง ๆ** |
| soft DEF ← VIT/AGI | **เลเวลล้วน** + passive ให้ตรง ๆ |
| HIT ← DEX/LUK · FLEE ← AGI/LUK | **เลเวลล้วน เท่ากันทุกตัวละคร** |
| CRIT ← LUK | **ฐานคงที่ `CRIT_BASE_BP` 5%** ที่เหลือมาจากเกียร์ ตรงกับ Genshin และ HSR |
| ASPD ← AGI/DEX | **หยุดนิ่งเองเมื่อค่าหยุดโต** กลายเป็นค่าประจำคลาสกับอาวุธ ตามที่ดีไซน์ต้องการ |

**level-up ไม่แจกแต้มแล้ว** ค่าทั้งหกค้างอยู่ที่ค่าฐานของคลาสตลอดไป ผลข้างเคียงที่ดีคือ ASPD
กลายเป็นค่าคงที่โดยไม่ต้องไปแก้สูตร FJK ที่ซับซ้อนเลยสักบรรทัด

⚠️ **แก้คำอ้างที่แรงเกินไป** ตารางข้างบนคือสูตรที่ **เลิกอ่าน** หกค่าแล้ว ไม่ใช่ว่าไม่มีใครอ่านเลย
ยังมีอีกแปดจุดที่อ่านอยู่ และเป็นรายการที่ต้องเคลียร์ก่อนจะลบฟิลด์ได้จริง

| สูตรที่ยังอ่านอยู่ | อ่านอะไร | ดีไซน์ตอบไว้ว่าอย่างไร |
|---|---|---|
| ASPD | AGI, DEX | SPD เป็นค่าประจำตัวละคร §4.5.1 |
| cast time | `DEX×2 + INT` | Haste §4.5.1 |
| MaxSP | INT | ลบ SP ทั้งระบบ §3 |
| SP reserve capacity | `10 + INT/10` | ลบพร้อม SP §3 |
| soft MDEF ของมอน | INT | MDEF ถูกลบไปแล้วจากทางเดินดาเมจ §4.5.1.8 เหลือเฉพาะทางนี้ |
| ATK/MATK ของ **มอนและเพ็ต** | STR/DEX/INT | ⚠️ ยังไม่มีคำตอบ ต้องมีเส้น ATK ของตัวเอง |
| การ์ดใบหนึ่ง | STR | ⚠️ ยังไม่มีคำตอบ |
| `buffed_stats` | พับบัฟ StrAdd AgiAdd VitAdd IntAdd DexAdd AllStatAdd AgiPct DexPct | ลบบัฟกลุ่มนี้พร้อมสกิลที่ให้มัน §4.5.2 |

เพราะค่าหยุดโตแล้ว ทุกสูตรข้างบนจึงได้ **ค่าคงที่ต่อคลาส** ซึ่งบังเอิญตรงกับที่ดีไซน์อยากได้
สำหรับ ASPD และ SP แต่ **มันยังผูกอยู่ ไม่ใช่ไม่ได้ใช้** ลบฟิลด์ตอนนี้ยังไม่ได้

**HP ต้องฟิตใหม่** เพราะตัวคูณจาก VIT หายไป ทำให้ HP ตกราว 9-10% ปรับเส้น HP ของคลาสขึ้นตามอัตรานั้น
แล้วค่ากลับมาตรงเดิม swordsman 25,527 · mage 13,059 · thief 18,247

**ผลกับเส้นความคืบหน้า** 114 / 201 kills เทียบกับ 112 / 200 ก่อนสไลซ์นี้ โซนและเลเวลตรงกันทุกจุด

⚠️ **สิ่งที่หายไปจริง ๆ และควรรู้** สาย **หลบ** กับสาย **ตีไวจาก AGI** ไม่มีอีกแล้ว ความแม่นกลายเป็น
การเทียบเลเวลล้วน ๆ ซึ่งเป็นสิ่งที่ตั้งใจ แต่แปลว่า **มอนที่หลบเก่งต้องเขียนค่า `mob_flee` ไว้ในดาต้า**
ไม่ใช่ได้มาจาก AGI อีกต่อไป

### 4.5.2 สิ่งที่ช่วยให้ราคาไม่แพงอย่างที่คิด

- **มอนสเตอร์ใช้ stat แบนอยู่แล้ว** `mob_hit` `mob_flee` และ `max_hp` ที่เขียนตรง ๆ โดยข้ามสูตร
  ของผู้เล่น ทางเดินแบบแบนจึงมีอยู่จริงในสิม ผู้เล่นแค่ย้ายมาใช้ทางเดียวกัน
- **BuffKind ฝั่งค่าปลายมีครบแล้ว** AtkPct AtkAdd MatkAdd DefPct HardDefAdd HpPct MaxHpAdd
  AspdPct HitAdd FleeAdd DmgReducePct
- **BuffKind ที่ถูกลบ** StrAdd AgiAdd VitAdd IntAdd DexAdd LukAdd AllStatAdd AgiPct DexPct AgiSlowAdd
  ตัวที่ต้องหาของแทนคือ AgiSlowAdd ที่ Frost Bolt ใช้สโลว์ ย้ายไปใช้ SPD ลดโดยตรง

## 5. Potential Board (แทน skill tree + skill point)

ยืมโครงจาก **CZN Potential** (บอร์ด node ปลดด้วยวัสดุ, ผสม stat กับ effect, เพดานสองชั้น)
แทนที่จะเป็น "4 สกิล อัพ 1→10 แยกกัน" แบบ HSR — เพราะเกม idle ที่ผู้เล่นจะมี 15 ตัว
ต้องการ **จำนวนครั้งที่ต้องกดน้อยแต่ทุกครั้งมีความหมาย**

> **14 node ต่อตัวละคร เป็นเส้นตรง ไม่มีกิ่ง** — 4 skill node ที่อัพ 1→10 และ 10 stat node
> ที่ซื้อครั้งเดียว รายละเอียดผังอยู่ที่ §5.1 ถึง §5.4

### stat node ต้องไม่ซ้ำกับ Soul Paths
ทั้งสองเป็น "ตารางโหนดที่ให้ stat" ถ้าไม่แบ่งหน้าที่ มันจะแย่งวัสดุกันเองและเพิ่มงานบาลานซ์เป็นสองเท่า

| | ให้อะไร | ขอบเขต |
|---|---|---|
| **Soul Paths** | stat พื้นฐานกว้าง ๆ (HP/ATK/DEF/CRIT) | **ทั้งบัญชี** |
| **Potential stat node** | **+% stat หลักของคลาสนั้น** และ **+% ดาเมจธาตุของตัวมันเอง** | **ตัวละครตัวเดียว** |

ตัวที่ทำให้ไม่ซ้ำแน่ ๆ คือ **"+% ดาเมจธาตุของตัวเอง"** — Soul Paths ทำไม่ได้เพราะเป็นของบัญชี
ไม่รู้ว่าใครถือธาตุอะไร และมันไปเสริมชาร์ตสะสมธาตุอีกทาง

**stat ที่ติดมากับ node บนเส้น spine** (ผูกกับบทบาทของ node นั้น ไม่ใช่พลังรวม):
Skill-1 → +% ATK/MATK · Skill-2 → +% DEF/HP · Ultimate → **+% Charge Rate** · Passive → +% stat หลัก
ประมาณ **+10% ต่อแกนเมื่อเก็บครบ** — รู้สึกได้ แต่คำนวณเพดานล่วงหน้าได้ตอนจูน

### 5.1 ผังโหนด — 14 โหนด เส้นตรง

ปลดตามลำดับ โหนดก่อนหน้าต้องปลดแล้วเสมอ ไม่มีกิ่งให้เลือก

| # | โหนด | ให้ |
|---|---|---|
| 1 | stat | ATK +3% |
| 2 | **skill · Skill-1** | Lv1 → 10 |
| 3 | stat | HP +4% |
| 4 | stat | DEF +4% |
| 5 | **skill · Skill-2** | Lv1 → 10 |
| 6 | stat | ATK +3% |
| 7 | stat | Element DMG +4% |
| 8 | **skill · Basic** | Lv1 → 10 |
| 9 | stat | HP +4% |
| 10 | stat | DEF +4% |
| 11 | stat | Charge Rate +6% |
| 12 | **skill · Ultimate** | Lv1 → 10 |
| 13 | stat | ATK +4% |
| 14 | stat | Element DMG +6% |

รวมเมื่อเก็บครบ ATK +10% · HP +8% · DEF +8% · Element DMG +10% · Charge Rate +6%

skill node เป็นโหนดเดียวที่ซื้อซ้ำได้ 10 ครั้ง (Lv1→10) stat node ซื้อครั้งเดียว
โหนดที่ 1 ปลดฟรีตอนได้ตัวละคร ทำให้กดครั้งแรกอยู่ที่ Skill-1 ซึ่งเป็นสกิลที่ผู้เล่นเห็นผลทันที

### 5.2 Exemplar ไม่ให้ bonus stat — เคาะ 2026-09-07

**Exemplar ไม่มี stat line ของตัวเอง** ค่าของตัวละครมาจากสามทางเท่านั้น

| ทาง | ให้ |
|---|---|
| **ค่าฐานของตัวละคร** | เส้นโค้ง HP ATK DEF ตาม §4.5.1.2 |
| **Potential Board** | §5.1 |
| **เกียร์ + Soul Paths** | ของบัญชี/ของสวมใส่ |

ก่อนหน้านี้ Exemplar เป็น stat stick (flat + % + แกนที่สาม) ซึ่งทำให้มีสองระบบที่ให้ stat
ต่อตัวละครซ้อนกัน และทำให้ตัว SSR แรงกว่าเพราะตัวเลขไม่ใช่เพราะ kit

**ดาว (ตัวซ้ำ) = Resonance ทำหน้าที่แบบ Eidolon** ปลดเพดานสกิลและเพิ่ม effect ไม่ใช่ให้ stat
seraphine กับ lucielle ทำแบบนี้อยู่แล้ว (re-level สกิลต่อดาว) อีก 8 ตัวยังเป็น stat stick
ต้องเขียน kit ให้ก่อนถึงจะถอด stat line ออกได้โดยไม่เหลือตัวว่าง

⚠️ **ลำดับงานที่บังคับ** สร้าง Potential Board ในสิมก่อน แล้วค่อยถอด stat line ของ Exemplar
ถ้าถอดก่อน จะได้ตัวละคร 8 ตัวที่ไม่ให้อะไรเลย

### 5.3 แบบ Trace ของ HSR — **เคาะแล้ว 2026-09-07 ใช้ผังนี้**

§5.1 (เส้นตรง CZN) และ §5.4 (รายการ ZZZ) เก็บไว้เป็นบันทึกของทางที่ไม่ได้เลือก

#### โครงจริงของ HSR

Trace ของ HSR เป็นต้นไม้กิ่ง ประกอบด้วยของสามชนิดที่ปนกันอยู่บนผังเดียว

| ชนิด | จำนวน | อัพยังไง | ปลดยังไง |
|---|---|---|---|
| **Ability trace** | 4 (Basic · Skill · Ultimate · Talent) | ไต่ทีละเลเวล 1→10 (Basic 1→6) | วัสดุ + credit |
| **Bonus ability (major trace)** | 3 (A · B · C) | ซื้อครั้งเดียว | Ascension 2 / 4 / 6 |
| **Stat bonus (minor trace)** | 10 | ซื้อครั้งเดียว | ต่อจากโหนดก่อนหน้าบนกิ่ง |

จุดที่เป็นหัวใจของผังนี้คือ **minor trace เป็นทางเดินไปหา major trace** ผู้เล่นไม่ได้เลือกซื้อ
stat เพราะอยากได้ stat แต่ซื้อเพราะมันขวางทางไป passive ตัวที่อยากได้ ทำให้ผังมีลำดับความสำคัญ
ในตัวเองโดยไม่ต้องเขียนกฎเพิ่ม และ Ascension เป็นเพดานสองชั้นที่กันไม่ให้ทุ่มวัสดุข้ามช่วง

Eidolon (ตัวซ้ำ) **ไม่อยู่บนผัง** และไม่ให้ stat — E3 กับ E5 ยกเพดานเลเวลสกิล +2 ที่เหลือเป็น effect

#### ผังที่เสนอ

**constellation** โยงกันแบบผัง trace ของ HSR — 17 โหนด ราก 1 จุด major trace 3 จุด
และมีเส้นเชื่อมข้ามกลุ่มทำให้ผังเป็นกราฟ ไม่ใช่ต้นไม้

```
                              [MAJOR A]
                                 |
                     s4 CRIT +2% |
                                 |
        s3 ATK +3% ------------- k1 Skill-1 1→10
            |                    |          \
            |                    s2 ATK +3%  \
            |                    |            \
   [MAJOR B] --- k2 Skill-2 --- s1 ATK +4%    s10 Element DMG +6%
        |         1→10           |             |
       s7 HP +4%                [ราก]          k3 Ultimate 1→10
        |                        |             |
       s6 DEF +4% ------------- s5 HP +4%   s9 Charge Rate +6%
                                              |
                                          s8 Element DMG +4%
                                              |
                                          [MAJOR C]

              k4 Basic 1→10 — เปิดเมื่อปลด major ครบ 2 ใน 3
```

**กฎการปลด** โหนดปลดได้เมื่อ **มีเส้นเชื่อมไปหาโหนดที่ปลดแล้วอย่างน้อยหนึ่งเส้น**
ไม่ใช่ "โหนดก่อนหน้าในลำดับ" — นี่คือความต่างจากเส้นตรง §5.1

เส้นเชื่อมข้ามกลุ่มมีสามเส้น (`s3—k1` · `s6—s5` · `k1—s10`) ทำให้ major หนึ่งตัวเข้าถึงได้จากสองทาง
ทางหนึ่งสั้นกว่าแต่ผ่านโหนดที่ไม่อยากได้ อีกทางยาวกว่าแต่ทุกโหนดระหว่างทางเป็นของที่ใช้จริง
**นั่นคือการตัดสินใจที่ผังนี้ขายจริง ๆ** ไม่ใช่แค่ "เลือกกิ่ง"

กิ่งไม่มีชื่อ ผู้เล่นเรียกมันด้วย major trace ที่อยู่ปลายทาง

- **10 stat node** (s1–s10) ซื้อครั้งเดียว รวม ATK +10% · HP +8% · DEF +4% · CRIT +2% ·
  Element DMG +10% · Charge Rate +6% — ยอดเท่ากับ §5.1 ย้ายที่วางเท่านั้น
- **4 skill node** (k1–k4) ไต่ 1→10 เหมือนเดิม
- **3 major trace** (A · B · C) คือ **passive ของ kit** ที่ §1 บอกว่ามี 2-3 อันต่อตัว —
  ไม่ได้แจกฟรีตอนได้ตัวอีกต่อไป แต่เป็นปลายทางของแต่ละกิ่ง

#### สิ่งที่ผังนี้ให้ ที่เส้นตรง §5.1 ให้ไม่ได้

- **ลำดับการลงทุนเป็นการตัดสินใจจริง** เล็ง major ตัวไหนก่อน และ**เดินทางไหนไปหามัน**
  ตัวเดียวกันในทีมคนละทีมเดินคนละทาง เส้นตรงไม่มีจุดนี้เลยเพราะลำดับถูกกำหนดไว้แล้ว
- **passive ของตัวละครมีที่อยู่ในระบบ** ไม่ใช่ของแถมที่ติดมากับตัว
- **stat node มีเหตุผลให้ซื้อทั้งที่ค่าน้อย** เพราะมันขวางทางไป major

#### ต้นทุนที่ผังนี้เพิ่ม

- โหนดต่อตัว 14 → 17 และผู้เล่นต้องอ่านผังก่อนกด (เส้นตรงกดตามลำดับได้เลย)
- ต้องเขียน **major trace 3 อันต่อตัวละคร** ซึ่งตอนนี้มีแค่ seraphine กับ lucielle ที่มี kit
- ปุ่ม "อัพให้สุดเท่าที่วัสดุมี" ต้องรู้ว่าจะเดินไปทางไหน — ให้ผู้เล่น**เล็ง major หนึ่งตัว**
  แล้วปุ่มเดินเส้นทางที่สั้นที่สุดไปหามัน ง่ายกว่าให้ตั้ง priority ของทั้งผัง
- **ผังเป็นงานศิลป์** เส้นตรงกับรายการวาดด้วย Control ธรรมดาได้ constellation ต้องมีตำแหน่งโหนด
  กับเส้นเชื่อมที่ออกแบบมือ

#### หนึ่งผังต่อ Doctrine ไม่ใช่ต่อตัวละคร — เคาะแล้ว 2026-09-07

HSR วาดผังต่อ **Path** ไม่ใช่ต่อตัวละคร ของเราวาดต่อ **Doctrine** → **5 ผัง** (Sentinel · Striker ·
Destroyer · Catalyst · Support) จบ ไม่ใช่ 15 ผังและไม่โตตามจำนวนตัวละครที่ออกใหม่

สิ่งที่ต่างกันระหว่างตัวละครสองตัวใน Doctrine เดียวกันคือ **major trace 3 อัน** และ **สกิลที่ k1–k4
ชี้ไป** ส่วนตำแหน่งโหนด เส้นเชื่อม และ stat บนโหนด ใช้ร่วมกัน หมายความว่าตัวละครใหม่หนึ่งตัว
กรอกแค่ค่าฐาน · kit · major trace 3 อัน ไม่ต้องออกแบบผังใหม่

**stat บนผังจึงต้องเข้ากับ Doctrine ไม่ใช่กับตัวละคร** — ผังของ Sentinel หนัก HP/DEF
ผังของ Striker หนัก ATK/CRIT ซึ่งตรงกับ profile ที่ §4.5.1.4 กำหนดไว้แล้ว

#### เพดาน

`ability trace level ≤ Job Level tier` และ `major trace A/B/C ปลดที่ tier 2 / 4 / 6`
ตรงกับ Ascension ของ HSR โดยใช้ Job Level tier ที่ §6 เลือกไว้แล้ว ไม่ต้องสร้างแกนใหม่

### 5.4 แบบ ZZZ — ไม่มีผัง มีแต่รายการ

#### โครงจริงของ ZZZ

ZZZ ไม่มี tree ไม่มีบอร์ด ไม่มีโหนด หน้าอัพตัวละครเป็น **รายการแบน**

| ชนิด | จำนวน | อัพยังไง | เพดาน |
|---|---|---|---|
| **Skill** | 5 (Basic · Dodge · Assist · Special · Chain) | ไต่ทีละเลเวล | promotion ของตัวละคร |
| **Core Skill** | 1 แถบ ไต่ A → F (6 ขั้น) | วัสดุเฉพาะ + Dennies | promotion |
| **Additional Ability** | 1 | **ไม่ได้อัพ** | เงื่อนไขทีม (faction / attribute ตรงกัน) |
| **Mindscape Cinema** | M1–M6 | ตัวซ้ำ | — |

จุดที่ต่างจาก HSR อย่างชัดเจน: **stat ทั้งหมดของตัวละครเกาะอยู่บน Core Skill ขั้นเดียว**
ทุกครั้งที่ดัน A→B→C ได้ทั้ง stat และ passive แรงขึ้นพร้อมกัน ไม่มี stat node แยกให้กดเลย
และ **Additional Ability ไม่ใช่ของที่ลงทุน** แต่เป็นรางวัลของการจัดทีม — เป็นระบบคนละก้อนกับการอัพ

Mindscape M3/M5 ยกเพดานเลเวลสกิล +2 เหมือน Eidolon E3/E5 ของ HSR

#### ถ้าเราใช้แบบนี้

- **4 skill** (Basic · Skill-1 · Skill-2 · Ultimate) ไต่ 1→10
- **Core** ไต่ A→F 6 ขั้น แต่ละขั้นให้ stat ก้อนหนึ่ง **และ** ดัน passive ของ kit ขึ้นหนึ่งระดับ
  รวมทั้ง 6 ขั้น = ATK +10% · HP +8% · DEF +4% · CRIT +2% · Element DMG +10% · Charge Rate +6%
  (ยอดเดียวกับ §5.1 และ §5.3 ต่างกันแค่รูปแบบการจ่าย)
- **กดทั้งหมด 10 จุด** ต่อตัวละคร เทียบกับ 14 (§5.1) และ 17 (§5.3)
- passive ของ kit ไม่ต้องเขียนเป็น 3 อันแยก เขียนเป็น **หนึ่งอันที่แรงขึ้นตามขั้น**

#### เทียบสามแบบ

| | §5.1 เส้นตรง (CZN) | §5.3 สามกิ่ง (HSR) | §5.4 รายการ (ZZZ) |
|---|---|---|---|
| จุดที่ต้องกด | 14 | 17 | **10** |
| ผู้เล่นต้องอ่านผังก่อนกด | ไม่ | **ใช่** | ไม่ |
| ลำดับการลงทุนเป็นการตัดสินใจ | ไม่ | **ใช่** | ไม่ |
| งานเขียน passive ต่อตัวละคร | ตามที่ kit มี | **3 อันแยก** | **1 อันที่ไต่ขั้น** |
| ตัวละครเดียวกันต่างทีมต่างกันได้ | ไม่ | **ได้** | ไม่ |
| เข้ากับ "อัพให้สุดเท่าที่วัสดุมี" | ได้ | ต้องมี priority ของกิ่ง | **ได้ตรงๆ** |

⚠️ ยังไม่เคาะ ทั้งสามแบบให้ยอด stat เท่ากันหมด ต่างกันที่จำนวนครั้งที่ต้องกด กับปริมาณงานเขียน
passive ต่อตัวละครใหม่หนึ่งตัว ซึ่งเป็นต้นทุนที่จ่ายซ้ำทุกตัวไปตลอดอายุเกม

### 5.5 กติกาของ major trace

เคาะ 2026-09-07 เลือกผัง **§5.3 สามกิ่งแบบ HSR** major trace = **passive ที่ปลายกิ่ง**

**major trace ทำอะไรได้**

| ทำได้ | ทำไม่ได้ |
|---|---|
| stat rider ที่มีเงื่อนไขผูกกับลูปของ kit | เพิ่มสกิลใหม่ที่ต้องกด |
| เขียนทับตัวเลขเดียวของท่าที่มีอยู่ | มีเลเวลให้ไต่ |
| คืนทรัพยากร (เกจ Limit Break) ตอน trigger | **ขยายรัศมี เปลี่ยนเป้า เพิ่มจำนวนครั้งที่ยิง** → เป็นของ ★ |
| utility เล็ก ๆ เช่น aggro | เพิ่มทรัพยากรใหม่ หรือ UI ใหม่ |

#### ของจริงใน HSR เป็นแบบไหน (สำรวจ 2026-09-07)

| trace | ผล |
|---|---|
| Bronya A2 *Command* | CRIT Rate ของ Basic ATK → 100% |
| Bronya A4 *Battlefield* | เริ่มการต่อสู้ พันธมิตรทุกคน DEF +20% 2 เทิร์น |
| Bronya A6 *Military Might* | Bronya อยู่ในสนาม พันธมิตรทำดาเมจ +10% |
| Gepard A2 | โดนศัตรูเล็งบ่อยขึ้น |
| Gepard A4 *Commander* | เมื่อ Unyielding Will ทำงาน Energy คืนเต็ม 100% |
| Gepard A6 *Grit* | ATK +35% ของ DEF ปัจจุบัน รีเฟรชทุกต้นเทิร์น |
| Seele A2 *Nightshade* | ฆ่าศัตรูได้ ดาเมจ +50% ซ้อน 3 ชั้น 3 เทิร์น |
| Seele A4 *Lacerate* | ระหว่าง Amplification ได้ Quantum RES PEN +20% |
| Seele A6 *Rippling Waves* | หลังใช้ Basic ATK แอ็กชันถัดไปเลื่อนเข้ามา 20% |

**ความซับซ้อนอยู่ที่เงื่อนไข ไม่ใช่ที่ผลลัพธ์** ผลลัพธ์เป็น stat หรือทรัพยากรแทบทั้งหมด
สี่รูปที่ใช้ซ้ำ: **stat rider ที่ผูกเงื่อนไขกับลูปของ kit** · **เขียนทับตัวเลขเดียว** ·
**คืนทรัพยากรตอน trigger** · **utility เล็ก ๆ อย่าง aggro**

ไม่มี trace ตัวไหนขยายรัศมี เปลี่ยนเป้า หรือเพิ่มจำนวนครั้งที่ยิง — ของพวกนั้นเป็นงานของ
**Eidolon** ซึ่งของเราคือ **Memory Fragment (★)** เส้นแบ่งนี้สำคัญเพราะมันตัดสินว่าไอเดียหนึ่งอัน
ไปอยู่ตรงไหน: ถ้ามันเปลี่ยน *รูปร่าง* ของท่า มันคือ ★ ถ้ามันเปลี่ยน *ตัวเลข* ภายใต้เงื่อนไข มันคือ trace

**เขียนได้ในหนึ่งประโยค** ถ้าเขียนไม่จบในประโยคเดียวแปลว่ามันควรเป็นสกิล ไม่ใช่ trace
ตัวเลขที่ต้องโตตามการลงทุนต้องไปอยู่บน skill node (k) ไม่ใช่ major trace —
นี่คือความต่างระหว่าง **Talent** (ไต่ 1→10) กับ **Bonus Ability** (ซื้อครั้งเดียว) ของ HSR

**หนึ่งกิ่งหนึ่งคำถามของ build** ปลายกิ่งทั้งสามต้องตอบคำถามคนละข้อ ไม่ใช่สามระดับของคำตอบเดียว
ถ้าผู้เล่นเปิดกิ่งไหนก่อนก็ได้ผลเหมือนกัน แปลว่าผังนี้ไม่ได้ให้อะไรเกินเส้นตรง §5.1

## 6. วัสดุ + เพดาน

**วัสดุ = Growth Stone แยกตาม "ธาตุ" × 3 ระดับความหายาก** (ตามแบบ CZN ที่ใช้ attribute-typed stone)
→ ธาตุกลายเป็นเหตุผลในการเลือกโซนฟาร์ม เสริมชาร์ตสะสมอีกทาง + เป็น commodity ให้ order-book

> ⚠️ **กับดักที่ต้องเลี่ยง:** เกมกาชาคุมวัสดุด้วย **stamina + domain รายวัน** ซึ่งเป็นกลไก
> **ต่อต้าน idle โดยตรง** — **ห้ามลอกมา** เรากำลังทำเกมที่ขายว่าไม่มีภาระรายวัน

**แหล่งวัสดุ:** ดรอปจากลูปฟาร์มปกติ (ไม่มี stamina ไม่มีวันประจำ) · ระดับสูงออกจาก **boss/elite room**
(ถูกจังหวะด้วย band อยู่แล้ว) · คุมอัตราด้วย **crowd-scaled drop** ที่ build ไว้แล้ว

**เพดานสองชั้น** (แบบ CZN ที่ใช้ Combatant Level + Leader Level):
- **Job Level** (ตัวละคร) — Job XP ยังมีหน้าที่ ไม่กลายเป็นซาก
- **Commander Level** (บัญชี) — ระบบที่ ship แล้วแต่ยังมีงานให้ทำน้อย ได้ความหมายเพิ่มทันที

⚠️ ค้างเคาะ: สูตรเพดาน (`node tier ≤ f(JobLv, CommanderLv)`) + ราคา node ต่อ tier

**UX ที่ต้องมีตั้งแต่วันแรก:** ปุ่ม **"อัพให้สุดเท่าที่วัสดุมี"** ต่อตัวละคร — เกมกาชาไม่ทำเพราะ
การกดคือ engagement ของเขา แต่ engagement ของเราคือวางแผนแล้วปล่อยให้เดิน

## 9. Build checklist

1. loc keys ของ Limit Break (§4) + ตรวจว่าหน้า Resonance ไม่ใช้คำ break/limit

10. Migration แต้มสกิล → วัสดุ (ทาง Engram refund)
