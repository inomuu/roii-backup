> elements — Physical, Fire, Thunder (Lightning), Water (Ice), Light, Dark — and nothing else is
> a design option: do not propose a unit, a weakness, a Sigil or a gear roll in a retired element,

## 1. ทำไมเปลี่ยน

matrix เดิม (`combat/damage.rs::element_mult_bp`) เป็นตาราง 150/50/100 ต่อคู่ธาตุ — ผู้เล่นต้อง
ท่องว่าอะไรชนะอะไร และ **ลงโทษ 50% เวลาธาตุไม่ตรง** ซึ่งอ่านยากและกดดันเกินไปสำหรับเกม idle

ระบบใหม่ยืมโครงจาก HSR/ZZZ: **ศัตรูประกาศธาตุที่ตัวเองแพ้เป็นรายการ** ผู้เล่นอ่านจาก bestiary
ตรง ๆ ไม่ต้องท่องตาราง

## 2. กติกา (ตัวเลขเคาะแล้ว)

```
ตีด้วยธาตุที่อยู่ใน weakness ของเป้า  → 12000 bp (120%)
ธาตุทั่วไป                            → 10000 bp (100%)
ธาตุที่อยู่ใน resist ของเป้า          →  8000 bp ( 80%)
```

- **ไม่มีบทลงโทษ 50% อีกต่อไป** — ธาตุไม่ตรงแค่ไม่ได้โบนัส
- `resist` เป็น **opt-in** ต่อมอน ใช้กับ elite/boss เท่านั้น (ดู §5)
- ช่องว่างระหว่างถูก/ผิดธาตุ = **1.5×** (120 vs 80) — ตั้งใจให้เบา แรงจูงใจในการเก็บตัวละคร
  ไปอยู่ที่ **break** (§6) ซึ่งกัดหลอดได้เฉพาะธาตุที่เป้าแพ้ ไม่ใช่ที่ตัวคูณ

**ผลข้างเคียงที่ดี:** ช่องว่างแคบกว่าเดิมมาก (เดิม 3×) → ดาเมจรวมแทบไม่ขยับ →
**ไม่ต้อง re-tune stat มอนทั้งกระดาน** และ goldens ขยับน้อย

**build แล้ว sim 0.0.329** — `combat::element_mult_vs(target, el)` อ่านลิสต์ของเป้า
ตารางเดิม 150/50 เหลือเป็น fallback ของเป้าที่ไม่มีลิสต์ (เซฟเก่า summon ผู้เล่น)
`resists` ยังว่างทุกตัว ผลจริงจึงเป็น 120/100 ตามที่ตั้งใจว่าเป็น opt-in
คำทำนายเรื่อง "ดาเมจรวมแทบไม่ขยับ" วัดแล้วจริง — seed 42 / 6000 ticks: kills 207 → 201

## 3. Neutral → **Physical**

`Element::Neutral` เปลี่ยน **ชื่อที่แสดง** เป็น **"Physical"** และกลายเป็นคีย์ weakness ที่ใช้ได้จริง
(มอนแพ้กายภาพได้ → ปาร์ตี้ดาบ/ธนูล้วนมีโซนบ้าน ไม่ใช่ธาตุตกสำรวจ)

> ⚠️ **ห้าม rename variant ใน Rust** — `Element::Neutral` เป็น `#[default]` และถูก serialize ลงทั้ง
> `game_data.json` (`"element": "Neutral"`) และเซฟ การเปลี่ยนชื่อ variant = data เก่าโหลดไม่ขึ้น +
> replay พัง **เปลี่ยนเฉพาะ display name** (EN ที่ส่งข้าม FFI + `strings.csv`)

### ชาร์ตสะสมฝั่งผู้เล่น (≠ enum ในสิม)

**`Element` enum ในสิมคงไว้ครบ 10 ตัวตามเดิม** — มอนเป็นธาตุอะไรก็ได้ ไม่ต้องแตะ
สิ่งที่จำกัดคือ **ชาร์ตฝั่งผู้เล่น** = ธาตุที่ "ตัวละครถือได้" ซึ่งผูกกับขนาด roster ที่ทีมเล็ก ๆ ทำไหว

**จำนวนธาตุตอนเปิดตัว 6** เคาะ 2026-09-07 คือ 5 ธาตุมาตรฐานเกมแฟนตาซีบวก Physical

**Earth / Wind / Poison / Spirit ถูกยกเลิก 2026-09-23** — ไม่มีมอนใช้ ไม่มีตัวละครถือ เหลือแค่การ์ดเก่าไม่กี่ใบ

เป็น niche ที่ไม่มีใคร build), `quiver_earth` ถูกถอด weakness `Wind` ของมอน 24 ตัวถูก retag เป็น Thunder

ผลพลอยได้ **ผู้เล่นฟรีเข้าถึงธาตุได้ตั้งแต่วันแรก** ผ่านตัวละครฐาน 5 ตัว → ทุบหลอดได้
โดยไม่เสียเงิน ตรงนโยบาย "ผู้เล่นฟรีต้องผ่าน PvE ได้" และ Exemplar เป็นรุ่นอัพเกรดของธาตุนั้น
ไม่ใช่กุญแจที่ฟรีไม่มี

**Spirit** เป็นของมอนเท่านั้น ghost-kind · **Poison** เป็นธาตุ DoT ของมอน ทั้งคู่ไม่เข้าชาร์ต

### กฎที่ทำให้ "เพิ่มธาตุทีหลัง" ไม่เจ็บ (user 2026-09-07)

ศัตรู **แพ้ได้หลายธาตุ** อยู่แล้ว การเพิ่มธาตุใหม่จึงไม่ทำให้เนื้อหาเก่าเสียหาย — แค่เติมธาตุใหม่
เข้าไปใน weakness list ของมอนที่ควรแพ้มัน

แต่ต้องเขียนจำนวน weakness เป็น **สัดส่วนของชาร์ต ไม่ใช่ตัวเลขตายตัว** ไม่งั้นแรงกดดันของระบบ
จะเปลี่ยนไปเงียบ ๆ ทุกครั้งที่เพิ่มธาตุ (2 จาก 5 = 40% แต่ 2 จาก 8 = 25%):

| ระดับ | สัดส่วนของชาร์ต | ที่ชาร์ต 6 ธาตุ |
|---|---|---|
| trash | ~40–50% | 2–3 ธาตุ |
| elite | ~20% | 1 ธาตุ |
| boss | ~40% | 2–3 ธาตุ |

⚠️ **weakness ต้องเป็นธาตุที่อยู่ในชาร์ตเสมอ** — weakness ที่ไม่มีตัวละครถือ = weakness ที่ตาย

## 4. นโยบาย: **ธาตุมาจากตัวละคร** — ⚠️ เคาะใหม่ 2026-09-19 (0.0.444)

> **ธาตุ = ธาตุโจมตี** — ตัวละครโจมตีเป็นธาตุ (Lapis = Fire, Aveline/Raplus = Dark, Lucielle = Light …)
> แต่**ไม่มีธาตุป้องกัน** (ไม่แพ้ธาตุ — ทำจริงตั้งแต่ 0.0.359) · **มอนสเตอร์ไม่มีธาตุ** มีแค่ **weakness list**
> (`weaknesses` / `resists`) — `MonsterDef.element` ถูกถอดออกจาก catalog ทั้ง 67 ตัว, matrix fallback
> ถูกลบ (ไม่มี list = 100% ทุกธาตุ), Holy Bane / `DmgVsElement` / Frozen อิง list แทน
> · **ธาตุที่มีจริงมี 6**: Physical (Neutral) · Fire · Lightning (Thunder) · Ice (id `Ice` ตั้งแต่ 0.0.475, save เก่าอ่าน `Water`) · Light (Holy) ·
> Dark (Shadow) — Earth / Wind / Poison / Spirit ใน enum เป็นซากของ class kit เก่า จะออกพร้อม class cleanup
> · ⚠️ ค้าง: กระจาย weakness ของมอน 67 ตัวใหม่ให้ครบ 6 ธาตุ (ตอนนี้ไม่มีมอนที่ weak Lightning/Light เลย)

> **ธาตุของดาเมจมาจาก "ตัวละคร + สกิล" เท่านั้น · เกียร์ / ลูกศร / การ์ด = ขยายผล ไม่ปลดล็อกคีย์**

เหตุผล: ถ้าซื้อ/ดรอปคีย์ธาตุได้ ระบบธาตุจะไม่กระตุ้นให้เก็บตัวละครเลย

| แหล่ง | เดิม | ใหม่ |
|---|---|---|
| ลูกศรธาตุ (`pick_ammo_idx`) | ให้คีย์ธาตุ | **เลิกให้คีย์** → เปลี่ยนแกนเป็น **ประเภทหัวลูกศร** (เจาะเกราะ / หัวหนัก / หัวมีเงี่ยง) ใช้โครง auto-swap เดิม |
| ธาตุบนอาวุธ (`gear_roll`) | ให้คีย์ธาตุ | **เลิกให้คีย์** → axis เปลี่ยนเป็น **"+X% ดาเมจต่อศัตรูธาตุ Y"** |
| การ์ดธาตุ | ให้คีย์ | เหมือนอาวุธ |
| สกิลแปลงธาตุอาวุธ (Ignite Break) | ให้คีย์ | **เก็บไว้** — เป็น skill node ที่ลงทุนด้วยตัวละคร ไม่ใช่เงิน |
| บัฟ `HolyDmgDealtPct` (Lucielle) | ขยาย | เข้ากฎอยู่แล้ว |

**ทำไมต้องเก็บลูกศรไว้ (แค่เปลี่ยนแกน):** `arrow_crafter` เป็น skill node ของ Ranger ที่ build แล้ว ·
ลูกศรเป็น **sink ของเศรษฐกิจ** ที่เดินตลอดเวลา (ดู `monetary-policy`) · เป็น identity ของ Archer

**⚠️ migration ของเกียร์เก่า:** ไอเทมที่ผู้เล่นถืออยู่ซึ่ง roll ธาตุมาแล้ว ต้องแปลงเป็น
"+% vs ธาตุนั้น" ตรง ๆ ตอนโหลด (ห้ามทิ้งค่า — ดู `migrate-item-must-not-rebuild`)

## 5. Plumbing (deterministic-safe)

- `MonsterDef` เพิ่ม `#[serde(default)] pub weakness: Vec<Element>` และ `pub resist: Vec<Element>`
  (default ว่าง → data เก่าโหลดได้)
- **bake ลง `Entity` ตอน spawn เป็น bitmask `u16`** (10 ธาตุ) ไม่ใช่ lookup ตอนตี
  → `element_mult_bp` ยังเป็น pure integer fn, **ไม่ต้องส่ง `GameData` เข้า damage path**,
  serialize ได้, **ไม่มี PRNG draw ใหม่ → draw order ไม่ขยับ**
- **ฝั่งผู้เล่นไม่ใช้ weakness mask** แต่ใช้ **Elemental RES%** รายธาตุ ดาเมจธาตุที่มอนตีใส่ผู้เล่น
  ถูกหักด้วย RES% ของธาตุนั้น (`skill-system-redesign.md` §4.5.1)
  ✅ **build แล้ว 0.0.359:** `element_mult_vs` ตอบ 100% ให้เป้าฝั่ง Player เสมอ (frozen ก็ไม่นับเป็น Water)
  ก่อนหน้านั้น unit ไม่มีลิสต์เลยตกไป matrix 150/50 — Lapis (Fire) โดน Water 150% / Earth 50% อยู่
- **`element` ของมอน = ธาตุโจมตีอย่างเดียว** (user 2026-09-12: "มีธาตุ แต่ player ไม่มี weakness")
  ไม่ใช่ identity: ไม่เกี่ยวกับ weakness, ไม่เกี่ยวกับ drop ใช้กำหนดว่าสกิล/basic attack ของมัน
  ติด debuff อะไรและโดน RES% ตัวไหนของผู้เล่น
- `pick_ammo_idx` / การเลือกสกิลตามธาตุ เปลี่ยนเกณฑ์จาก "ได้เปรียบไหม" → "อยู่ใน weakness ไหม"

### Migration ของมอน 67 ตัว
เขียนสคริปต์ derive จากตาราง `ADVANTAGE` เดิม: ธาตุที่ "ชนะ" ธาตุของมันวันนี้ → เป็น weakness ของมัน
(เช่น Water → weak Wind, Thunder) ได้ default ที่สมเหตุสมผลทั้งกระดานโดยไม่ต้องกรอกมือ
แล้วค่อยจูนมือเฉพาะ **elite/boss** — **ยังไม่เคยจูนมือ** (2026-09-13) ลิสต์ทั้ง 67 ตัวยังเป็นผลของ
สคริปต์ และตอนนี้ลำดับมีผลกับ drop แล้ว (§5.1) การจูนมือครั้งแรกจึงเป็นเรื่อง Potential ไม่ใช่ combat

### 5.1 weakness ตัวแรก = Sigil ที่มอนดรอป (0.0.355, `docs/potential-upgrade-design.md`)
Potential ใช้วัสดุ **Sigil** แยกธาตุตามตัวละคร (user: "ตาม element ไม่ใช่ doctrine") มอนดรอป Sigil ของ
ธาตุที่มัน **แพ้เป็นตัวแรก** — พา unit ที่ตีมันแรงสุดไป ก็ได้ของอัพตัวนั้นกลับมา; grade (I/II/III) ตามเลเวล
ของมอน; มอนไม่มีลิสต์จ่าย Essence แทน (`roll_potential_material`)

ผลที่ตามมา — **ข้อบังคับ coverage 18 cell** (6 ธาตุในชาร์ต × 3 grade): ทุกธาตุในชาร์ตต้องเป็น
weakness ตัวแรกของมอน ≥1 ตัวในทุกช่วงเลเวล (≤25 / 26-50 / 51+) ไม่งั้นตัวละครธาตุนั้นไม่มีที่ฟาร์ม
ในช่วงนั้น สถานะ 2026-09-13 (ก่อน data pass):

| | I | II | III |
|---|---|---|---|
| Physical | 4 | 1 | 3 |
| Fire | 5 | 1 | 5 |
| Water | 2 | 2 | 2 |
| Thunder | 2 | 1 | 4 |
| Holy | 3 | 3 | 4 |
| Shadow | 2 | 2 | 2 |

**ครบ 18 cell ตั้งแต่ 0.0.358 (data pass 2026-09-13)** — จูนมือครั้งแรกของลิสต์ 67 ตัว: reorder 21 ตัว
+ เพิ่ม Fire ให้ `baby_pinkling` 1 ตัว (combat ของตัวอื่นไม่เปลี่ยน — แค่ลำดับ) ล็อคด้วย ratchet
`tests/suite/potential_coverage.rs` สองข้อ:
- ทุกธาตุในชาร์ตเป็น weakness ตัวแรกของ **field monster** (ไม่นับบอส) ≥1 ตัวในทุก grade
- **ครบ 6 ธาตุใน zone ถึงเลเวล 20** (user: "ควรจะครบ 6 ธาตุภายใน area 20") — เพราะ **element area
  ปลดล็อคที่เลเวล 20** และรับหน้าที่แหล่ง Sigil หลักต่อจากนั้น (ยังไม่ build; ดู `potential-upgrade-design.md`)

ผลต่อ 4 area แรก (first weakness ของ pool / บอส):
```
area 1 lv1-5    Physical (greenling) + Fire (pinkling)      ★ Thunder   ← starter ทั้งสองฟาร์มได้ตั้งแต่นาทีแรก
area 2 lv6-10   Thunder + Physical                          ★ Shadow
area 3 lv11-15  Fire + Water                                ★ Holy
area 4 lv16-20  Water / Shadow / Holy / Fire                ★ Water
```

**Sigil ของธาตุนอกชาร์ต (Earth/Thunder/Poison/Spirit) ไม่มีวันดรอป** — weakness ที่ไม่มีตัวละครถือ =
weakness ที่ตาย ดังนั้น def เหล่านั้นไม่ควรอยู่ใน catalog จนกว่าจะมีตัวละคร

### กฎการวางเนื้อหา (ตัวที่ทำให้ "เก็บให้ครบธาตุ" ทำงานจริง)
- **แต่ละ band มีธีม weakness ของตัวเอง** → ตัวละครแต่ละธาตุมี "โซนบ้าน"
- **จำนวน weakness ต่อมอน = ตามสัดส่วนใน §3** (trash ~40–50% ของชาร์ต · elite ~20–25% · boss ~40%)
  — boss ควรมี ≥2 เสมอ (1 ธาตุ = ผนัง, 2 = ทางเลือก) · elite 1 ธาตุ = บททดสอบ specialist
- **ห้ามมอนตัวไหน weakness ว่าง** — โซนนั้นจะไม่มีระบบธาตุเลย
- **กฎผีของ RO ที่ต้องเก็บไว้:** มอน Spirit ได้ `resist: [Physical]` (อาวุธธรรมดาทะลุผี) และ
  weakness `[Holy]` — นี่คือเหตุผลของสาย Holy ทั้งสาย
- **ผนังต้องไม่ตัน** — ธาตุไม่ตรงแค่ช้าลง ไม่ใช่ตีไม่เข้า (นโยบาย "ผู้เล่นฟรีต้องผ่าน PvE ได้")

## 6. Toughness + Break

ตัวคูณธาตุ 120/100/80 เบาเกินกว่าจะทำให้ใครอยากเก็บตัวละคร **น้ำหนักทั้งหมดอยู่ที่ break**
ซึ่งกัดหลอดได้เฉพาะธาตุที่เป้าแพ้ (sim 0.0.326) — การเก็บธาตุจึงเป็นเงื่อนไขของการเข้าถึงกลไก
ไม่ใช่แค่ตัวเลขที่มากขึ้น

### 6.1 โมเดล **Toughness** — ยืมคนละครึ่งจาก Genshin กับ HSR/ZZZ

> **ชื่อ Toughness เคาะ 2026-09-07** เดิมเรียกหลอดนี้ว่า Resistance ซึ่งชนกับ **Elemental RES%**
> ที่เป็นแกนตั้งรับฝั่งผู้เล่น สองคำนี้อยู่ในคำศัพท์คอมแบตชุดเดียวกันและคนละความหมาย
> ตอนนี้จึงเป็น **Toughness = หลอดของศัตรู** และ **RES = การต้านทานธาตุของผู้เล่น**

ศัตรูมีหลอด **Toughness** (ค่าความทนทาน) ทุบให้หมดแล้วมันจะติดสถานะของธาตุที่ทุบหมัดสุดท้าย

| คำถาม | ใช้แบบ | กติกา |
|---|---|---|
| **สถานะอะไรจะติด** | Genshin (aura + trigger) | **ธาตุของหมัดที่ทุบหลอดหมด** เป็นตัวกำหนด |
| **ติดเมื่อไหร่** | HSR/ZZZ (เกจ) | **ต้องทุบ Toughness ให้หมดก่อน** ไม่ใช่ตีปุ๊บติดปั๊บ |

```
มอนแต่ละตัวมี toughness_max (u16, กำหนดใน MonsterDef — ต่อตัว ไม่ใช่ค่าคงที่ตามชั้น)

*** ทุก damage instance ทำ Toughness damage เป็นพื้นฐาน *** (user 2026-09-07)
    ตรง weakness เท่านั้นที่กัด (sim 0.0.326) · ธาตุอื่นลงดาเมจแต่หลอดไม่ขยับ
    สกิลที่มีโบนัส (toughness_dmg_mult) กินเพิ่มอีก

Toughness หมด → ดาเมจก้อน + stun + เปิดช่องรับดาเมจเพิ่มตลอดหน้าต่างนั้น (เท่ากันทุกธาตุ)
              → หลอดไต่กลับจนเต็มพอดีตอน stun หมด แล้วโตขึ้น 1.5 เท่าสำหรับครั้งถัดไป
```

**นี่คือที่ที่ระบบธาตุได้น้ำหนักคืนมา** — ที่ +20% เพียว ๆ ธาตุเบาเกินกว่าจะทำให้ใครอยากเก็บตัวละคร
แต่พอ **เฉพาะธาตุที่ตรงเท่านั้นที่กัดหลอดได้** ธาตุก็กลายเป็นเงื่อนไขของการเข้าถึงกลไก ไม่ใช่ตัวเลข
โดยที่คนธาตุไม่ตรงยัง **ไม่ถูกลงโทษ** แค่ไม่ได้เปิดกลไกให้

**หลอดเดียวรวม ไม่แยกรายธาตุแบบ ZZZ** เพราะ:
1. **เชียร์ทีมผสมธาตุ** — ทุกคนทุบหลอดเดียวกัน ต่างจาก ZZZ ที่ต่างคนต่างเติมหลอดใครหลอดมัน
   (ซึ่งลงโทษทีมผสม) — ตรงกับเป้าหมายเรื่องการเก็บตัวละคร
3. อ่านออกบนจอเกม idle — หลอดเดียวใต้เลือดมอน ไม่ใช่ 5 หลอด
4. **มันคือหลอด break แบบ HSR ที่ตัดทิ้งไปตอนแรก กลับมาโดยไม่ต้องเพิ่มระบบที่สอง**

⚠️ **กลับคำแล้ว** เดิมเขียนว่าไม่ต้องมี stat ใหม่ฝั่งผู้เล่น แต่ sim 0.0.321 เพิ่มสองตัวตามแบบ ZZZ
เพราะปาร์ตี้ครบ 5 คนแล้วไม่มีอะไรทำให้ break ถี่ขึ้นอีกเลย: **Break Build-up** (ความถี่ ควรมีเพดาน)
กับ **Break Damage** (มูลค่าต่อครั้ง ไม่ต้องมีเพดาน) ทั้งคู่ยังไม่มีแหล่งที่มา
ทุกอย่างเป็นจำนวนเต็ม **ไม่มีการสุ่ม → draw order ไม่ขยับ**

⚠️ **DoT ไม่ทำ Toughness damage** (ค่าเริ่มต้น) — พิษ/ไหม้เต้นทุกวินาที ถ้านับด้วยจะทุบหลอดแตกเองโดยไม่มีใครตั้งใจ

### 6.1.1 สถานะมีสองชั้น (ไม่งั้นสกิลเก่าพัง)

ถ้าทุกสถานะต้องผ่าน Toughness ก่อน **Frost Bolt จะไม่สโลว์ตอนตีโดนอีกต่อไป** และพิษของ Venom Edge
ก็หายไปด้วย — สกิลเหล่านั้นเสีย identity ของตัวเอง จึงแยกเป็นสองชั้น:

| ชั้น | ตัวอย่าง | ติดยังไง |
|---|---|---|
| **Skill debuff** (identity ของสกิล) | Frost Bolt สโลว์ · Venom Edge พิษ · Snare ตรึง | **ติดทันทีตอนตีโดน** ไม่ผ่าน Toughness |
| **Break** (เหมือนกันทุกธาตุ) | ดาเมจก้อน · stun · หน้าต่างรับดาเมจเพิ่ม | **ต้องทุบ Toughness หมดก่อน** |

โอเวอร์เลเวลแค่ไหน ตอนนี้ผลออกมาดีเพราะเลือดมอนโตตามแบนด์ทันดาเมจปาร์ตี้พอสมควร แต่ถ้าวันไหน
ไม่ทัน ระบบจะเงียบหายไปเอง **ทางที่ทนกว่าคือผูกหลอดกับ HP ของมอน** เพื่อให้ break เกิดที่จุดเดียวกัน
ของชีวิตมอนเสมอ ⚠️ ยังไม่ได้ทำ

### 6.2 บอส ≠ มอนธรรมดา — ต่างกันที่ "ความยาวหลอด"

วิธีเดียวกับที่ ZZZ และ HSR ใช้ (บอสหลอดยาวกว่าชัดเจน) และ **`toughness_max` ต้องจูนต่อตัว
ไม่ใช่ค่าคงที่ตามชั้น** (user 2026-09-07) — มอนธรรมดาด้วยกันก็มีค่าต่างกันได้

| | `toughness_max` | ความรู้สึกที่ต้องการ |
|---|---|---|
| trash | สั้น | แตกได้ราว 1 ครั้งต่อการตายหนึ่งตัว |
| elite | กลาง | ต้องตั้งใจหน่อย |
| **boss** | **ยาวมาก** | หลอดที่สองที่ค่อย ๆ ขยับ = **จังหวะดราม่าของฉากบอส** + เป็นเหตุผลให้มี build สายเจาะสถานะ |

(ตัวเลขข้างบนเป็นจุดตั้งต้นสำหรับ seed ค่า ไม่ใช่กฎ)

**Seed ค่าให้มอน 67 ตัวโดยไม่ต้องกรอกมือ:** ตั้ง `toughness_max` เป็นสัดส่วนของ HP (หรือของ band)
ด้วยสคริปต์ แบบเดียวกับที่ derive weakness list แล้วค่อยจูนมือเฉพาะบอส/elite

**วัดผลตอนจูน:** คอลัมน์ `breaks` ใน CSV ของ `sim-cli` (มีแล้ว) — ตัวเลขที่ใช้จริงคือ **breaks ต่อ kill**

### 6.3 Anomaly ประจำธาตุ + Disorder — **ถอดออกจาก scope 2026-09-08**

**เหตุผล:** sim 0.0.324 เคาะว่า **break เป็นเหตุการณ์เดียวกันหมดไม่ว่าธาตุไหนเป็นคนทุบ**
(ดาเมจ + stun + หน้าต่างรับดาเมจเพิ่ม) และความต่างระหว่างตัวละครย้ายไปอยู่ที่ **Break Trigger**
รอยที่ค้างตามธาตุจึงไม่มีที่ยืนในโครงนี้ — มันคือความต่างที่ break ไม่มีแล้วโดยตั้งใจ

ของเดิมที่ถอดออก (เก็บไว้ในประวัติ git ที่คอมมิตนี้): Disorder (ใส่ธาตุใหม่ทับธาตุเดิม
แล้วระเบิด) และ anomaly 6 ตัว — Physical/Assault · Fire/Ignition · Water/Freeze→Shatter ·
Wind/Cyclone · Holy/Sanction · Shadow/Umbra

**ถ้าจะกลับมาทำ** มันต้องเป็น**ชั้นที่ซ้อนบน** break ที่เหมือนกัน ไม่ใช่ตัวที่ทำให้ break ต่างกัน
เช่นสถานะที่ติดจาก **สกิล** ของตัวละครนั้น ๆ ไม่ใช่จากการทุบหลอด — ซึ่งเป็นระบบคนละก้อนกับ break
และตรงกับที่ ZZZ แยก anomaly ออกจาก daze อยู่แล้ว
