# สำรวจโค้ดเรนเดอร์ 2D → ถ้าจะเปลี่ยนเป็น HD-2D (3D)

สำรวจ 2026-08-13 จากโค้ดจริง ไม่ใช่การประเมิน · คู่กับ `docs/budget-plan.md`
ต้นแบบที่ใช้ทดสอบลุคอยู่ที่ `godot/proto/hd2d_probe.gd` (ทิ้งได้ ไม่ผูกกับอะไร)

---

## 0. ข้อสรุปก่อน

**สิม บริดจ์ และ UI ทั้งหมดไม่ต้องแตะ** — สิมส่งพิกัดจำนวนเต็มบนกริด 24×12 จะวาดเป็น 2D
หรือ 3D เป็นเรื่องของชั้นนำเสนอล้วน ๆ งานทั้งหมดอยู่ใน `godot/views/` เฉพาะชั้นโลก

| กลุ่ม | บรรทัด | สถานะ |
|---|---|---|
| ใช้ต่อได้ทั้งดุ้น (ข้อมูล/คอนฟิก) | ~700+ | ไม่แตะ |
| สลับชนิดโหนด ตรรกะรอด | ~3,175 | ปรับ |
| **เขียนใหม่จริง (immediate-mode)** | **~2,030** | **รื้อ** |
| UI / วิว / เน็ต ที่เหลือ | ~21,000 | ไม่แตะ |

รวมที่ต้องแตะ **~5,200 จาก 27,377 บรรทัด ≈ 19%**

---

## 1. สถาปัตยกรรมปัจจุบัน

**ระบบพิกัด** — `cell_px` (~32) + `origin` แปลงช่องเป็นพิกเซล
`field_area()` คำนวณกรอบสนามจากขนาดวิวพอร์ตลบพื้นที่ HUD แล้ว `_recompute_layout()` เรียกใหม่ทุกครั้งที่ resize
→ **ใน 3D ทั้งก้อนนี้ถูกแทนด้วยกล้องตัวเดียว**

**ชั้นการวาด** — เป็น `Node2D` ลูกของ Arena แยก CanvasItem กันเพื่อคุมการกรองภาพต่างกัน

| ชั้น | ใช้ทำอะไร | การกรอง |
|---|---|---|
| `_grid_layer` | พื้น/ฉากหลัง **แคชไว้ วาดใหม่เฉพาะตอนเปลี่ยนโซน** | NEAREST |
| `_field_layer` | ออร่าพื้น (Sanctus ฯลฯ) | LINEAR (ขอบไล่เฉดจะเป็นแถบถ้า NEAREST) |
| `_fx_layer` | เอฟเฟกต์การตี/สกิล | NEAREST |
| `_glow_layer` | แสงเรือง | — |
| `_draw()` ของ Arena เอง | ตัวละคร เงา หลอดเลือด หลอดร่าย ตัวเลข ชื่อ | — |

**ที่เป็นโหนดจริงอยู่แล้ว** — `BaseMonster extends Node2D` + `AnimatedSprite2D` (มี `draw_` แค่ 2 จุด)
มอนสเตอร์จึงย้ายง่ายที่สุด เพราะเป็นโหนดอยู่แล้ว ไม่ใช่ immediate mode

**ที่ยังเป็น immediate mode** — `arena_draw.gd` 862 บรรทัด 72 จุดวาด คือแกนที่ต้องรื้อ

**คำสั่งวาดที่ใช้จริงทั้งหมด**
`draw_rect` ×26 · `draw_set_transform` ×18 · `draw_texture_rect` ×9 · `draw_arc` ×9 ·
`draw_texture_rect_region` ×8 · `draw_circle` ×8 · `draw_string` ×7 · `draw_line` ×3

## 2. ไฟล์ต่อไฟล์

### ใช้ต่อได้ ไม่ต้องแตะ
- **`render_data.gd` (489)** — ค่าคงที่ ตารางปรับแต่ง `sprite_cells()` `size_mult()` `HIT_FX_DEFS`
  `PROJECTILE_SPRITE` เป็นข้อมูลล้วน **probe ใช้ตัวนี้ตรง ๆ แล้วและได้สเกลถูกต้อง**
- **`monster_catalog.gd`** — คอนฟิกรายมอนสเตอร์ (`fw`/`fh`, `clips`, `hit_frame`) ข้อมูลล้วน
- **สไปรท์ชีททั้งหมด** — HD-2D ใช้สไปรท์เป็น billboard งานอาร์ตที่จ่ายไปแล้วไม่เสียเปล่า

### สลับชนิดโหนด ตรรกะรอด
- **`base_monster.gd` (470)** — `Node2D`→`Node3D`, `AnimatedSprite2D`→`Sprite3D`
  ตรรกะ `hit_frame` / คลิป / flinch / death ไม่ต้องแก้
- **`enemy_animator.gd` (342)** — ตัวจัดการ ส่วนใหญ่รอด บรรทัด `node.scale = ...` กลายเป็น `pixel_size`
  และ `self_pos` กลายเป็น `Vector3`
- **`player_animator.gd` (951)** — ไฟล์เดี่ยวที่ใหญ่ที่สุด ผู้เล่นกลายเป็น `Sprite3D` แบบเดียวกับมอนสเตอร์
- **`arena.gd` (935)** — วางระบบ อินพุต ฉากหลัง แสง
  `field_area()` / `cell_px` / `origin` ถูกแทนด้วยกล้อง
  ⭐ **`_adopt_scene_lights()` / `_apply_daylight()` / `_apply_light_time()` มีอยู่แล้ว** — เกมมีแนวคิด
  เรื่องแสงต่อโซนอยู่ก่อนแล้ว ต่อเข้ากับไฟ 3D ได้ ไม่ต้องคิดใหม่
- **`companion_view.gd` (430)** — แพเนล SubViewport เปลี่ยน `Camera2D`→`Camera3D`
  ⚠️ **เสียการซูมจำนวนเต็มแบบคมกริบ** (โค้ดเขียนกำกับไว้เองว่า "pixel-clean")
- **`zone_layout.gd` (123)** — เครื่องมือ authoring แนวคิดตาราง `cells` รอด เปลี่ยนจาก
  TileMapLayer เป็นตัวสร้างเรขาคณิต **และเพราะทั้ง 180 โซนเป็น 24×12 เท่ากันหมด สร้างอัตโนมัติได้**

### ต้องเขียนใหม่จริง
- **`arena_draw.gd` (862)** — แกนของงาน คำสั่ง `draw_*` ไม่มีคู่เทียบใน 3D ทุกอันต้องกลายเป็นโหนดจริง
- **`arena_fx.gd` (609)** — เอฟเฟกต์การตี กระสุน → `Sprite3D` แบบยิงครั้งเดียว หรือ `GPUParticles3D`
- **`number_fx.gd` (357)** — ตัวเลขดาเมจ
- **`field_fx.gd` (200)** — ออร่าพื้น → ควอดจริงวางบนพื้น **อันนี้ง่ายขึ้นใน 3D**

## 3. กุญแจสำคัญ: ไม่ต้องแปลงทุกอย่างเป็น 3D

`draw_rect` 26 จุด + `draw_string` 7 จุด ส่วนใหญ่คือ **หลอดเลือด หลอดร่าย ตัวเลขดาเมจ ชื่อที่ชี้**
ของพวกนี้ **ไม่ควรอยู่ในโลก 3D** — ให้อยู่บน `CanvasLayer` 2D ต่อไป แล้วใช้
`Camera3D.unproject_position()` แปลงตำแหน่งโลกเป็นพิกัดจอทุกเฟรม

ได้สามอย่างพร้อมกัน: ตัดความซับซ้อนของ `arena_draw.gd` ไปมาก · ตัวหนังสือคมเท่าเดิมไม่ต้องสู้กับ
เปอร์สเปกทีฟ (เราเคยเจอปัญหานี้แล้วตอนทำซูม ต้องเปลี่ยนไปใช้ฟอนต์ MSDF) · และ UI ทั้งเกมไม่ต้องแตะ

**เส้นแบ่งที่ควรใช้: อะไรที่เป็นโลก → 3D · อะไรที่เป็นข้อมูลบอกผู้เล่น → 2D ทับบนจอ**

## 4. ที่ง่ายขึ้น

- **การเรียงหน้าหลัง** — depth buffer จัดให้ ส่วน y-interleave ระหว่างผู้เล่นกับมอนสเตอร์ที่เคยทำมือหายไป
- **ออร่าพื้น** — ควอดวางบนพื้นจริง แทนการปลอมเปอร์สเปกทีฟด้วยวงรี
- **เงา** — เงาจริงจากไฟ แทน `art/fx_shadow.png` ที่แปะใต้ตัว
- **ลำดับชั้น** — ไม่ต้องจัด `_fx_layer` / `_field_layer` / `_glow_layer` เอง

## 5. ที่ยากขึ้นหรือเสียไป

- **ซูมจำนวนเต็มแบบคมกริบในโหมดหน้าต่างมุมจอ** — 2D ซูม 2× ได้พิกเซลใหญ่ขึ้นคมกริบ
  3D ทำไม่ได้เพราะสไปรท์เป็นควอดในเปอร์สเปกทีฟ **และมันไปตกที่โหมดที่เป็นตัวตนของเกมพอดี**
- **การแคช `_grid_layer`** — ตอนนี้พื้นวาดครั้งเดียวต่อโซน 3D เรนเดอร์ใหม่ทุกเฟรม
- **การกรองภาพรายชั้น** (NEAREST vs LINEAR ต่อชั้น) กลายเป็นการตั้งค่าต่อวัสดุ
- **ต้นทุน GPU** — จาก ~0 กลายเป็นของที่ต้องคุม (ดู §6)

## 6. บทเรียนจากต้นแบบ

- **ทำได้บน `gl_compatibility` เดิม** — Compatibility รองรับ 3D + ไฟ + เงา + glow + หมอก
  **ไม่ต้องย้าย renderer = แผนมือถือไม่ต้องทิ้ง** สิ่งเดียวที่ทำไม่ได้คือ depth of field
  (volumetric fog ก็เป็นของ Forward+ เท่านั้น)
- **เงาไฟจุด (omni) เป็น cubemap = เรนเดอร์ 6 หน้าต่อดวง** สองดวงคือ 12 รอบของ geometry ทั้งฉาก
  → ปิดเงา omni ใช้เงาจากไฟหลักดวงเดียว และตั้ง `SHADOW_ORTHOGONAL` แทน cascade 4 ชั้น
- **`ArenaRenderData.sprite_cells()` ใช้ได้ตรง ๆ ใน 3D** — 1 หน่วยโลก = 1 ช่อง แล้ว `pixel_size`
  คือ cells-per-art-pixel พอดี
- **ขอบโปร่งใสใต้เฟรมวัดจากภาพได้** แทน `foot_drop` ที่จูนมือรายมอนสเตอร์ใน `monster_catalog.gd`
- **Sprite3D ต้องใช้ billboard เต็ม + จุดหมุนที่ขอบล่าง** ถึงจะหันเข้ากล้องโดยเท้าไม่ลอย
- ⚠️ **ยังวัด GPU ไม่ได้จริง** — `ioreg` Device Utilization เป็นของทั้งเครื่อง และตอนวัดมี
  Android emulator + Xcode Instruments + Godot อีกตัวรันอยู่ (ค่าฐาน ~49%) **ตัวเลขทั้งหมดยังไม่สรุป**

## 7. ลำดับที่ควรทำถ้าเอาจริง

1. **พื้นก่อน** — สร้างเรขาคณิตจากตาราง `cells` ของ `zone_layout.gd` (อัตโนมัติ 180 โซน)
2. **มอนสเตอร์** — `BaseMonster` → 3D (ง่ายสุด เพราะเป็นโหนดอยู่แล้ว)
3. **ผู้เล่น** — `player_animator.gd` ตามหลัง ใช้รูปแบบเดียวกัน
4. **ย้าย HUD ในโลกไปเป็น 2D ทับจอ** — หลอดเลือด/ตัวเลข/ชื่อ ผ่าน `unproject_position()`
   (ตัด `arena_draw.gd` ไปได้มากที่สุดต่อแรงที่ลง)
5. **เอฟเฟกต์** — `arena_fx.gd` / `field_fx.gd` ทีละอย่าง ของเก่ายังใช้ได้ระหว่างทาง
6. **โหมดหน้าต่างมุมจอ** — ทำท้ายสุด เพราะเป็นที่ที่ข้อแลกเรื่องซูมจะเจ็บที่สุด

**ที่ยังไม่รู้และไม่เกี่ยวกับโค้ดเลย: tileset 20 ไบโอม** ซึ่งเป็นก้อนเดียวที่ต้องใช้เงินจริง
งานโค้ดทั้งหมดข้างบนทำเองได้ ฉากต้องจ้าง
